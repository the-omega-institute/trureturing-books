# 持续模型研究与形式化

目标是发展解释力更强、可检验且推导可靠的模型。物理学可以从基本假说出发；不要求把每个基本假说都变成无条件数学定理。持续寻找可以从更基础前提推出的假设、实际模型构造、表示与等价关系、有效近似的误差界及新的可检验后果，并将可靠成果回写本书。

## 开始与接续

1. 阅读项目的 `AGENTS.md`、项目规则、验证契约与已有相关研究记录。确认用户当前范围、两个仓库的工作区、未完成 PR、已有证据及下一步；先接续未完成的实质工作。没有现成记录时直接从当前问题开展研究，不先建立全量假设目录、固定编号或登记系统。
2. `trureturing` 按用户显式路径、已有 `TRURETURING_DIR`、默认 `~/trureturing` 的顺序选择。将选定根目录通过 `TRURETURING_DIR` 传给后续步骤，引用其他 skill 的相对路径示例不能覆盖这个选择。在该仓库核对远程、分支与工作区所有权，再按上游隔离规则复用或创建 linked worktree；遵守其当前 `CLAUDE.md`、`agents/CONTEXT.md`、规范与 `skills/codex-formalize/SKILL.md`。本书库不存放 `.lean` 文件，也不改模板托管文件。
3. 选择一个能推进当前问题的独立目标；沿真实证明依赖拆解，不按章节数量凑成果。候选来源可以是正文假设、推导中的缺口、实验偏差或前一轮的残余问题，不预设真假或可形式化性。

## 科学目标与命题边界

已有书稿问题先定位权威语言原文，优先使用其已有章节锚点或环境 ID，并检查其他语言和直接依赖的媒体；新问题保留其来源与准确陈述即可，不要求预先存在书稿或编号。写清本批要解决哪个具体问题，按内容采用以下路线，可在同一问题下保留不同子问题：

| 内容 | 研究交付 |
| --- | --- |
| 数学假设 | 从明确的基础前提导出它，或给出满足全部前提的构造、反例、必要充分条件；找不到证明时保留具体缺口。 |
| 物理基本假说 | 明确对象与操作含义，推导定量后果、参数范围及可区分的预测；现实适用性由观测检验。 |
| 有效模型或近似 | 写明尺度、极限和范数，尝试证明被忽略项的误差及失效边界，不把近似声称为任意条件下精确成立。 |
| 哲学诠释或类比 | 保留作者原声；先找可独立陈述和检验的结构主张。没有数学内容时不制造通用谓词来包装成定理。 |

判断模型是否更好时，比较其覆盖的现象、预测精度、独立假设与自由参数、适用范围及新预测。区分用于拟合的数据与独立检验的数据；没有运行实验或核对原始资料时只记录预测方案，不写成实验支持。

对候选定理写出量词、类型、定义域、基础前提、待消去的假设和结论，建立原文到形式陈述的逐项对应。特别核对：

- 条件定理仍是定理，但只有从其余前提真正推出假设，才算消去了该假设。把假设装进结构字段再读出、重命名或改作定义，均不算证明它。
- 构造一个满足条件的实例，不证明一切物理对象都属于这类实例；有限维、单比特或特定更新律的结果保留相应范围。
- 涉及分组、取商或可区分性时，核对数学上的相等关系与物理不可区分性是否一致；表示不同不能直接当作状态可区分，所选等价关系会影响哪些量被保留。更换表示后，验证原演化与新表示的对应关系，据此确定比较对象与误差量。
- 涉及近似或反复演化时，先固定参照模型与误差量；更换参照对象后核对演化与比较目标是否改变，必要时将模型间差异计入误差预算。区分固定步数的误差界与对时间、步数、维数一致的控制。边缘态接近不自动控制联合态的相关性，须检查误差界实际需要的量。
- 证明更弱或修正后的命题时，明确其与原主张的差别；不据此宣布原主张整体已证明。
- 数值与反例搜索用于探索；有限采样不代替普遍证明。证明失败不代表不可证明，某组前提的反例不代表整个研究纲领失败。
- 需要从有限观测或估计值外推全域模型结论或误差界时，明确所需的结构或正则性、目标域覆盖与统计假设及其独立依据，不能只凭同批数据拟合或预设待证表示来验证这些前提；据此前提推导观测与估计误差、未观测区域的控制及统计不确定性如何传递到目标结论或界，注明适用的置信水平与未获支持的前提。

## 一批研究如何落地

需要规划证明路线或保留交接证据时，参考 [研究方法与证据](references/batch-method.md)。记录服务于研究，不作为开始研究的额外前置。

1. **先检索再证明。** 在当前钉版与上游现状中找相同或更强的冻结声明，再查所钉 mathlib 和相关原始文献。已有结果直接复用；按上游规则处理已有理论卷或 atom，不为书稿造重复声明或仅改名的包装。
2. **先做数学研究。** 明确成功和反例判据，手推透明特例，尝试一般化与独立数值核对。优先做能补上原模型真实缺口的构造、表示、稳定性与误差界；不要仅为“有一条 Lean 定理”选择无关恒等式。
3. **再做上游形式化。** 采用 [theorem-formalize](../theorem-formalize/SKILL.md) 的跨仓库流程和上游现役规约；新增内容按上游要求交付 D5 Lean、Blueprint Scribe、实际消费关系、冻结及所需登记。完成适用的内核、公理闭包、构建、独立审查与机器门；不得用 `sorry`、私有公理或改判官来通关。经验假说用显式前提表达，不能通过新增公理取得“已证”。
4. **回写准确范围。** 上游合入并冻结后按 [trureturing-pin](../trureturing-pin/SKILL.md) 钉到实际包含成果且可从配置分支到达的提交。先改中文，再同步自然准确的英文；定理盒逐项对齐 GID，解释证明与物理含义放在盒外。只升级被证明覆盖的句子，剩余假说、文献结果、诠释及开放问题继续明确标识。
5. **验证消费者。** 运行 `./tbook check` 至少零错误。影响书稿时构建对应双语输出并检查日志与适用的自动校验结果；普通导出页面仅在 [book-export](../book-export/SKILL.md) 的视觉排查条件成立时查看，不默认遍历深浅主题与手机宽度。影响工具时运行工具测试。引用或锁变动后更新声明地图数据、对应静态图及缩略图；可视化与静态图仍按各自 skill 看图，媒体证据框逐项核对，不能因为 GID 有效就把新外推染绿。

## 两个仓库的 PR 与合并

两个仓库可以并行准备与审阅，依赖顺序不能颠倒：

1. 上游 PR 指向 `trureturing` 的实际集成分支，通常为 `dev`；写清数学问题、书中消费者、准确范围与验证。书库依赖 PR 可以先作为草稿，保留现有合法钉版，不引用尚未冻结的声明或 PR head。
2. 在当前用户授权范围内推进 push、PR、修复及 merge；用户已授权本轮两仓 PR 与合并时不重复请示。skill 文件本身不授予未来会话新的发布权限；已有授权继续有效。
3. 上游当前候选通过其必需检查与适用独立审查后合并，确认实际合并提交及冻结状态片。若冻结由后续提交产生，等待真实状态，不以合并状态替代冻结。
4. 刷新书库分支与锁文件、核对陈述摘要变化并完成书稿验证，使依赖 PR 脱离草稿；通过书库当前候选的必需检查与适用审查后合入 `main`，核对实际合并提交和 Pages 部署。
5. 两个 PR 互相链接并关联研究批次。上游 PR 的交付说明可以引用先开的书库草稿链接；存在性不等于依赖已满足。不能宣称跨仓库原子合并。权限或分支保护阻断时保留可审查成果和具体缺口，不绕过 required checks。

复用既有冻结结果时可只需书库 PR；研究无新数学成果时不造空上游 PR。若用户只要求构建或改进本 skill，交付可复用指引及实际验证，不据此擅自启动无界研究或无关仓库变更。用户明确要求继续研究时，按下面的接续循环执行。

## 持续研究与 skill 迭代

在项目已有记录中保留接续必需的信息：研究范围、实际结果、残余假设、证据、两仓 PR/提交、冻结 GID、验证与下一步；必要时新增一份简洁研究笔记，不强制特定文件名、表格、编号或状态机。数学结果与发布状态分别说明；未合并、未冻结、未验证部署均不能写成全流程完成。

持续研究已获授权时，沿依赖关系推进下一个可执行子问题；一条路线遇到缺口时记录具体原因，改走有依据的构造、反例或误差界路线，不为同一失败原样重试。外部任务在运行时做不依赖它的授权工作。

每批检查本 skill 是否因真实经历暴露出缺失指引或误导：只有得到实际证据时才做最小改进，提炼能处理同类未知问题的方法，而不是把本次假设、结论、失败个案、路径或编号固化进 skill。具体证据留在项目研究材料中。修正本 skill 不能降低证明、原文忠实或发布标准；用未参与原修订的情景核对泛化效果，不写仅匹配措辞的测试。

“持续”指研究可以跨会话接续，不表示本 skill 自带定时器、后台任务或无限权限。用户指定预算、范围或停止时遵从；没有独立研究路径、缺少必需资料或外部状态长期阻断时，保存可接续证据并如实报告，不能宣称所有假设已获证明。
